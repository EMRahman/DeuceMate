DeuceMate Archive Safety

What used to go wrong with a saved match archive, and what each recent change does about it. The iPhone archive is the copy of record; iCloud is a one-way backup; the Watch keeps only its newest 25 matches. Every scenario below is about one rule: a file that can't be read is never treated as an empty archive.

Where match data lives, and the three guards

Matches flow one way: Watch → iPhone → iCloud. Three checks now sit on that path. Each scenario below is one of them doing its job.

Scenario 1 · #228

The archive can't be read, and the backup gets wiped

One match with a value this build doesn't know (an older app reading a newer match, or a retired enum case) fails the decode of the whole file, because the archive is read as one list. Before #228, that one failure travelled all the way to iCloud.

Before

The list showed "No Matches Yet". The next debounced push replaced the iCloud backup with an empty archive.

Now

  • matchHistory.json, deletedMatchIDs.json and forgottenPlayers.json are all checked; any one failing pauses everything.
  • The Matches screen shows Matches Couldn't Be Opened (I/O, may clear) or Matches Couldn't Be Read (damaged) instead of "No Matches Yet".
  • Leftover .corrupt files from older builds, and an initialized archive missing its files, pause too.

Pinned by undecodableMainIsPreservedInPlaceAndSuspendsWritesExportsAndBackupAcrossRelaunch oldQuarantineBlocksLegacyMigrationAndRecoversCleanlyOnReplace

Scenario 2 · #228

Matches leave the iPhone with nothing to explain it

Scenario 1 is one way to lose matches; there could be others. So every backup push now checks one thing: if a match the backup holds is missing here, is there a deletion that explains it? Deleting the only match still empties the backup, because its tombstone explains the loss.

Before

Every push wrote whatever the iPhone held, with no floor. Any local loss became the backup's loss.

Now

  • The Matches screen shows iCloud Backup Paused, and the iCloud indicator says "iCloud backup paused".
  • Bring Them Back reads the withheld matches from the backup into the iPhone. Remove from Backup lets only those matches go, after copying the backup aside.
  • A confirmed Replace import counts as an explanation; Merge never removes anything, so it never needs one.

Pinned by unexplainedLossKeepsTheBackupsRecords deletingTheOnlyMatchStillEmptiesTheBackup withoutAManifestTheBaselineIsReadFromANewerFormatBackup

Scenario 3 · #228

Switching iCloud accounts

Risk

The manifest records what this iPhone pushed to one account. Compared against a different account's backup, it could wave through a push that replaces that account's matches, or drop its deletions.

Now

  • The manifest carries the iCloud account's identity. On a mismatch, or with no manifest, the store reads the destination backup's ids instead.
  • Before any push, the backup's own tombstones and forgotten players are merged in. A remote ledger it can't read is left untouched rather than overwritten.

Pinned by switchingICloudAccountInspectsDestinationAndUnionsRemoteLedgers removeFromBackupRejectsStaleAccountBaselineAfterAccountSwitch

Scenario 4 · #228, #231

A save that didn't save

Manual entry, End at Current Score and Delete Permanently used to update the list first and write second. If the write failed, the screen and the Watch had already moved on.

Before

The save looked fine. After a relaunch the match was missing, or a deleted match came back on the iPhone while the Watch copy and the note were already gone.

Now

  • Manual entry and End at Current Score show Match Not Saved; the form or report stays open.
  • Delete Permanently shows Match Not Deleted inside its own popover. An alert presented while that popover closes may never appear.
  • While the archive is paused, the manual-entry button is disabled.

Pinned by savedMatchThatCannotBeWrittenChangesNothingAndSavesOnceWritable permanentDeletionThatCannotBeWrittenKeepsTheMatch saveAndDeleteWhilePausedAreRefusedAndChangeNothing

Scenario 5 · #231

A delete that happened anyway

#228 writes the deletion files first, so that a crash halfway through a delete still completes it at the next launch. But a write that fails (rather than crashes) after those files left the new tombstone on disk while telling the user the match wasn't deleted.

Pinned by deleteThatFailsAfterItsTombstoneIsWrittenLeavesNoTombstoneBehind forgetThatFailsAfterTheLedgerIsWrittenLeavesTheLedgerAsItWas · removing the fix makes both fail

Scenario 6 · #228

A Watch delivery fails to save on a healthy archive

Before

The merged matches appeared in the list, the write failed, and Sync Now reported success. After a relaunch they were gone, and the Watch had no reason to send them again.

Now

  • The delivery is held in pendingWatchRecords and retried with the next delivery or full sync.
  • The Matches screen shows Watch Matches Couldn't Be Saved with Try Again, which asks the Watch for its full history.
  • Sync Now doesn't claim success while anything is waiting. Once a retry saves, tags and match-type changes are reconciled back to the Watch.

Pinned by failedWatchWriteSuppressesSyncSuccessAndRetriesAtFullSync retryReconcilesCommittedMetadata · the held copy lives in memory only (see open items)

Scenario 7 · #229

A file written by a newer version of DeuceMate

The Watch and iPhone apps update separately, so an older app regularly meets data from a newer one. Before #229 that was reported as damage, or as a raw decode error. Now a file that states a newer version gets its own diagnosis, and that diagnosis outranks the others.

FileBeforeNow
appState.json (Watch live match)Decoded first, version checked after; a newer file read as damageVersion checked before decoding. Writes blocked, file kept: Saved match requires a newer version of DeuceMate.
forgottenPlayers.jsonUnsupported version counted as damagedVersion checked before reading ids: Update DeuceMate to Read Matches, offering Save a Copy only
Manual export fileVersion had to equal 1 exactly. The first bump would have rejected every existing exportAccepts a range of versions; a newer file says "Update DeuceMate to import it"
Match history, tombstones, Watch wire formatBare JSON lists onlyReaders accept a bare list or a versioned envelope. Writers still write bare lists

Limit until step 2

No build writes the envelope yet. A newer app that adds an enum case still writes a bare list, so an older iPhone reads it as damaged (Matches Couldn't Be Read) rather than newer. That still fails closed. Only the clearer message waits for step 2.

Precedence

newerVersion > undecodable > unreadable. The "newer" screen hides Restore from iCloud, so an older backup is never offered over files a newer app wrote.

Scenario 8 · #229

The Watch can't read its live match or its history

Before

  • An unreadable live state was replaced with a fresh match, and the next point overwrote the file.
  • Unreadable history showed "No past matches yet."

Now

  • Live state that can't be read is kept and writes stop: Saved match could not be read. It has been preserved; scoring is unavailable.
  • History shows History Unavailable. Finishing a match then fails visibly ("Match could not be saved. Try again before leaving.") and the live match is kept.

Pinned by unsupportedZeroAppStateVersionBlocksWritesAndPreservesFile and the Watch StatsStoreTests envelope cases

The ways out

Every recovery is a deliberate tap on the Matches screen. Nothing recovers on its own, and nothing destructive happens without a copy.

Before replacing anything: the current files are copied to MatchArchive/Recovered/<time>/. If the copy fails, nothing is replaced. The Health sidecar is never copied there.
Matches Couldn't Be Opened unreadable

A file exists but iOS couldn't open it. Often temporary.

  • Try AgainRe-reads the files. On success, saving resumes and the Watch is asked for its full history.
Matches Couldn't Be Read undecodable

Damaged, or written by an app that adds a value this build lacks. Retrying won't help.

  • Restore from iCloudReads the backup one match at a time, keeps the local Health data, and says how many matches stay behind for a newer app.
  • Save a CopyShares the kept files and leaves them in place.
  • Replace importSettings › Backup & Transfer. Merge stays refused while paused.
Update DeuceMate to Read Matches newerVersion

A file states a version newer than this app supports.

  • Save a CopyThe only action offered. Updating the app is the fix.
iCloud Backup Paused push withheld

The backup holds matches this iPhone lost, with no deletion recorded.

  • Bring Them BackAdds those matches back to the iPhone from the backup.
  • Remove from BackupCopies the backup aside, then lets only those matches go. No tombstone, so the Watch can still send them back.
